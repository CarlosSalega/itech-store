# Apple Catalogue Extension

Add the Apple products that the current catalogue does not sell yet, taken from a third
source, as committed data plus local photography — without the repository carrying any
reference to that source.

Branch: `feat/apple-catalog-extension`. Route: inline (one dependent unit, no parallel
work). Commits: work units on this branch only; push, PR and merge stay the owner's call.

## Specs

- **S1** — The catalogue gains the Apple models it does not have today: iPhone 18 Pro,
  iPhone 18 Pro Max, iPhone Duo, Apple Watch SE 3 (two colours), Apple Magic Keyboard for
  iPad, Apple Pencil Pro, Apple Pencil USB-C, and the Apple 20W adapter. Each one arrives
  with its own photography under `public/products`, referenced through the existing
  `/products/...` convention.
- **S2** — "no olvides que no debes dejar huella de otro proyecto que no sea itech-store".
  Read strictly: the repository carries no host, vendor name, logo, contact channel, URL,
  provenance field, source price or source identifier for the source, in code, committed
  data, comments, tests, README, this document, commit messages or script output. The base
  address is read from an environment variable that has no default, and no script loads a
  `.env` file on its own.
- **S3** — Only products whose model is absent from the current catalogue are imported, and the
  decision is an explicit, reviewed list of Apple product names rather than an inference from the
  source: `REQUESTED_APPLE_PRODUCTS` in `src/features/catalog/apple-catalogue.ts`. A product the
  store already sells under another source's naming is simply not requested, so it cannot enter
  twice; a new model enters by having its name written in that list. Amended during T6 — the
  original wording asked the adapter to derive model identity from the name, which was rejected in
  L5 after the real names showed that any key collapsing `Apple MacBook Neo 8GB 512GB citrus` into
  `Apple 13" MacBook Neo - A18 Pro` also collapses `iPhone 17` into `iPhone 17 Pro Max`.
- **S4** — Products that are not Apple are excluded (the source also lists non-Apple items
  and generic accessories).
- **S5** — Prices and stock are not imported. They stay synthetic, generated by
  `prisma/seed.ts` from category and storage, and the sample-price warning keeps applying.
- **S6** — Existing behaviour is preserved: the three data files merge into one catalogue,
  `featured` still picks the first slug per category, and a missing image file still drops
  only that reference instead of failing the seed.

## Log

- **L1** (owner request) — "ahora revisa [el catálogo de la tercera fuente] asi scrapeamos mas
  imagenes de apple, no olvides que no debes dejar huella de otro proyecto que no sea
  itech-store". The address given by the owner is deliberately not reproduced here: S2, the
  owner's own constraint in the same sentence, forbids this repository to identify the
  source, and this document is part of the repository. What the sentence asks for is fully
  preserved: more Apple products with their photography.
- **L2** (inventory measured before deciding) — the catalogue today holds 80 products, 88
  variants across the two data files, 182 image references and **0 missing image files**;
  only 4 products carry no photography at all. So the request is not about filling image
  gaps: the photography is complete for everything already sold. What the third source adds
  is catalogue.
- **L3** (the source shape) — a server-rendered listing page holding all 47 products in one
  response: each card carries the name, an already-normalised price and one webp photograph.
  No pagination to walk and no JavaScript bundle to parse, unlike the second source, so this
  adapter is materially simpler than `scripts/extract-iphone-catalog.ts`.
- **L4** (owner decision on the overlap) — the source overlaps the existing catalogue at
  model level, and its naming differs from both existing sources: `Apple Airpods Pro 3`
  against the committed `Airpods Pro 3`, five colour-split iPhones against one `iPhone 16`,
  `Apple Watch Serie 11 46MM Black` against `Apple Watch Series 11 - Caja Aluminio Negro - ...`.
  Importing all 47 would show customers two entries per model. The owner chose "solo lo que
  falta": import only models absent from the catalogue (S3). Options that were offered and
  rejected: import everything with names unified across sources, import everything verbatim,
  and replace the Apple family with this source.
- **L5** (the duplicate rule is a reviewed list, not an inference) — the first design derived a
  model key from every name and compared it against the catalogue, so a product appearing in two
  sources would be imported once. It was rejected after seeing the real names: `Apple MacBook Neo
  8GB 512GB citrus` against `Apple 13" MacBook Neo - A18 Pro` are the same model, and any key that
  collapses them also collapses `iPhone 17` into `iPhone 17 Pro Max`. Cheap heuristics here fail in
  both directions — a lost product or a duplicate — and both are silent. The policy is instead the
  explicit list of Apple product names in `scripts/extract-apple-catalogue.ts`, reviewed by the
  owner once: a product the store already sells under another source's naming is simply not
  requested, and a new model is added by writing its name. The list is also the authoritative
  spelling, so the store owns the product name rather than inheriting the source's, which carries a
  doubled brand on some rows (`Apple Apple Watch SE 3 40mm`).
