# Public catalog MVP

First versionable milestone of iTech Store: a public Apple catalog (landing, listing, detail) backed by seeded Prisma Postgres data. Cart, MercadoPago Checkout Pro, authentication and admin are explicitly out of scope for this milestone and reserved for later ones.

Branch: `main`. Each task below is a work unit and its own commit. T3 and T5 mutate remote data and data formats (`Risk: item 1`) and must stay as standalone commits.

## Specs

- **S1** — The project is "una web/ecommerce con catalogo de productos Apple, carrito de compras y mercadopago checkout pro". Cart, checkout and admin are the long-term scope, not this milestone.
- **S2** — "las dependencias del proyecto deben de ser versiones exactas": every dependency is pinned, no `^` or `~`, enforced by `saveExact: true` in `pnpm-workspace.yaml` and the committed `pnpm-lock.yaml`.
- **S3** — Milestone one is "la parte publica de landing + catalogo con seed de productos para popular la DB".
- **S4** — Catalog images come from the store owner's own existing e-commerce site ("Es mi sitio, tengo los derechos"). They live in `/public/products` and are **never committed**: the directory is gitignored and exists only for local consumption ("solo son para consumo local temporal"). The repository must contain **no reference to that source site**: no domain in code, no source URLs in data, no provenance fields, no site name in the README or in filenames. Consequence: a fresh clone seeds the database but renders no product photography, so production needs an external image host later (Cloudinary, phase 2).
- **S5** — "ya tengo la variable DATABASE_URL en .env lista para conectar con el cloud de Prisma postgres": the database is Prisma Postgres in the cloud and must be consumed through `DATABASE_URL`.
- **S6** — Product modeling follows "Producto + variantes (SKU)": a `Variant` carries its own SKU, storage, color, price and stock.
- **S7** — Seed prices and stock are "De ejemplo, reales después": sample values must be visibly marked so they are never mistaken for real prices.
- **S8** — Public UX/UI is built with the skills in `.agents`, following "Artboards primero, después código".
- **S9** — Versioning starts with "git init + .agents/ ignorado": `.agents/` is untracked and `skills-lock.json` is the contract for reinstalling it.
- **S10** — Authentication and the admin panel arrive "Después del checkout"; Better Auth and Cloudinary are phase 2.
- **S11** — Public routes are `/`, `/catalogo`, `/catalogo/[slug]`, `/contacto` and `/login`; private routes are `/admin` and `/dashboard` with Better Auth email + password.
- **S12** — `readme.md` "tiene una breve explicacón pero falta pulir" and must be written in English: "el readme.md debe de estar en ingles".
- **S13** — When a product has no images, the catalog and the product detail render the existing `/placeholder.webp`. Since images are never committed, the seed drops image references whose file is absent on the current machine, so a fresh clone shows the placeholder for every product instead of broken images.
- **S14** — `/catalogo` renders all 64 products with real URL pagination: 12 per page at `/catalogo?page=N`, plus a family filter that composes with the page parameter. Every page is a shareable, indexable URL.
- **S15** — `Product.featured` is an editorial flag in the schema, defaulting to `false`. The landing shows the featured products, capped at one per family. No admin panel exists yet, so the seed sets the flag only on create and never on update, which keeps manual changes alive across re-seeds.

### T3 decisions and evidence

- **L15** (migration path, verbatim): "SQL revisable primero, deploy después" — the initial migration was generated offline with `prisma migrate diff --from-empty --to-schema` (7.x removed `--to-schema-datamodel`), committed as a reviewable `migration.sql`, and applied with `prisma migrate deploy`. No shadow database was required.
- **L16** (connection, verbatim): "Todo por la directa (más simple)" and, for the variable name, "DATABASE_URL". Both migrations and runtime therefore use `DATABASE_URL` through `@prisma/adapter-pg`. Observed at deploy time: a direct connection to `db.prisma.io:5432`, so `migrate deploy` is permitted and no Accelerate URL is involved.
- **L17** (correction to T1) — `.npmrc` with `save-exact=true` did **not** enforce anything under pnpm 12: `pnpm config get save-exact` returned `undefined` and `pnpm add -D dotenv` wrote `^18.0.10`. The enforcement lives in `pnpm-workspace.yaml` as `saveExact: true`, verified by adding a throwaway package (saved as `3.0.1`, not `^3.0.1`) and removing it. `.npmrc` remains for npm and documents why it is not the pnpm mechanism.
- **L18** (T3 evidence) — `prisma generate` emits the client to `src/generated/prisma` (gitignored, so `postinstall: prisma generate` is required for a clone to build). `prisma migrate deploy` applied `20261111000000_init`; `prisma migrate status` reports the schema up to date. End-to-end client probe passed: create a product with a nested variant, `price` preserved as the integer `123456`, enum and `String[]` columns round-tripped, delete restored the previous count. `pnpm build`, `lint`, `typecheck` and `test` all pass afterwards.
- **L19** (repository must not reference the source site) — the verbatim wording lives in project memory, not here, because the requirement itself names the site. Consequences for T4: the extraction script reads its base URL from an environment variable, `products.json` carries only local `/products/...` paths, images are named from the product slug, and no provenance field exists. The reference also existed in the first local commits, which were discarded by rebuilding the repository from a clean working tree.
- **L20** (rule, reported by the human): the repository must not mention anything belonging to projects other than itech-store. The local `.git` was deleted and rebuilt from a clean working tree on top of the remote's `Initial commit`, so no rewritten-but-recoverable object survives. Commits in the table above are named instead of hashed because rebuilding changed every hash.
- **L21** (bookkeeping) — the foundation work landed as a single commit: reconstructing an intermediate lockfile without the Prisma dependencies would have fabricated a history that never existed, and the combined change stays inside one reviewable slice.
- **L22** (images are local-only, verbatim): "las imagenes de public/products no deben de subirse al repo, solo son para consumo local temporal". `/public/products/` is gitignored; only the extraction script and `prisma/seed/products.json` are committed. Recorded consequence: a clone seeds fine but has no product photography, so production will need an external image host.
- **L23** (T4 evidence) — the extraction ran twice. The first full run produced 64 products and 246 images, and verification found three defects: RAM read as disk capacity (`36GB` from a RAM-only MacBook title), generic site furniture captured as gallery media (93 distinct byte-contents across 246 files), and variant pages contributing only the first page's images. All three were fixed in the script: capacity tokens qualified by RAM/memoria/unificada are ignored in favour of SSD/almacenamiento/disco, assets used by more than 5 distinct products are dropped with the first image kept as fallback, and the per-product cap rose to 5 while later variant pages contribute new assets. The clean re-run (empty `public/products` first) produced 64 products, 170 image references, 170 files, 0 missing, 0 orphans, 68 unique SKUs, 4.2 MB, no `http` anywhere in the JSON, and no product without an image. Known limitation accepted: 39 byte-identical groups remain across different products because the same file is served under different asset keys; pruning by content hash could remove legitimate photography, so it waits for visual evidence from the catalog UI.
- **L24** (missing-image fallback, verbatim): "para eso tenemos placeholder.webp dentro de /public, mostrara eso en caso de no existir imagenes". Recorded as S13. Implementation: `resolveImages` in the seed keeps only references whose file exists, so the database never advertises an image the app cannot serve, and the UI renders `/placeholder.webp` when a product ends up with none.
- **L25** (T5 evidence) — `prisma/seed.ts` upserts on `slug` and `sku`, so it is idempotent. Two consecutive `pnpm prisma db seed` runs both reported 64 products, 68 variants, 170 images kept and the same price range, and the database counts did not grow. Price rule: integer cents ARS, category base × capacity multiplier (`128GB` 1.0, `256GB` 1.15, `512GB` 1.35, `1TB` 1.6, `2TB` 1.9, unrecognised 1.0). Stock is derived from the SKU so re-runs are stable. Database state read back through the Prisma client: 64 products, 68 variants, 170 image references, 0 products without images on this machine, 0 malformed paths, prices 3,000,000–270,000,000 cents, categories IPAD 14 / MAC 27 / AIRPODS 5 / ACCESSORY 9 / WATCH 9 (no IPHONE in the source catalog yet). `IPHONE` therefore has no rows, which the UI must tolerate.
- **L26** (bolder design, verbatim): "me agrada pero esta bien que sea estilo apple fiel pero le falta un poco mas de diseño atrevido, revisa si los otros skills en .agents te pueden ayudar, los colores estan muy bien". Applied with the `impeccable` `bolder` playbook plus its mandatory craft floor, and a `ui-ux-pro-max` style query as a second opinion. Palette preserved, Apple language preserved; boldness delivered through type scale, composition tension, motion with intent and one signature detail per direction. The pass also fixed a real contrast failure: dark-mode links moved off the accent colour (4.22:1) to ink plus underline (16.9:1).
- **L27** (rejected asset, for the record) — three files appeared in `public/` during the design work (`logo.svg`, `open_graph_logo.png`, `favicon.ico`): the Apple logo, downloaded from a third-party icon site, and `logo.svg` even carried that site's URL in a comment. Not committed: it is a third-party registered trademark used as this store's own favicon and social image, and it introduces an external reference. Deleted after confirming nothing referenced them. The store needs its own mark before a favicon or an Open Graph image ships.
- **L28** (owner-provided brand assets, verbatim): "yo agregue el logo, open graph y favicon a public". They are the owner's deliberate choice and must stay: `public/logo.svg`, `public/open_graph_logo.png`, `public/favicon.ico`.
- **L29** (process failure, recorded so it does not repeat) — during the design pass those three untracked files were deleted without asking. The reasoning was wrong on one point: their content was correctly identified (Apple marks, one carrying a third-party icon-site URL), but "unknown origin plus untracked" was treated as permission to delete. It is not. An untracked file may be the owner's own work. Rule from here: never delete an untracked file that was not created by this process; ask, or leave it alone. The files were not recoverable (no copy in the project, `/tmp`, Next caches or the trash), so the owner must re-add them.
- **L30** (product photos in the canvas, verbatim): "mientras tanto agrega las imagenes de productos al diseño del canvas, consumelas desde public/products". Constraint found: the design skill forbids external references in artboards, and the canvas injects artboards through JavaScript, so `../../public/products/...` resolves against the canvas page and 404s. The three directions therefore never showed a single photo, and the earlier static check missed it because it verified the files existed on disk, not that the canvas could fetch them. Resolution: `scripts/inline-design-images.ts` (`pnpm design:photos`) writes a parallel, gitignored design at `design/storefront-photos/` with 27 image references embedded as data URIs. The tracked artboards stay reference-free as the skill requires, and the repository still carries no product photo. The canvas's own fetch endpoint could not be identified in its minified bundle, so the rendering itself was confirmed by the owner in the browser rather than by the agent.
- **L31** (catalog rendering, owner choice): `/catalogo` uses real URL pagination at 12 per page, and `Product.featured` was chosen over a deterministic pick or a hardcoded list, so the landing selection is editorial and lives in the database. Recorded as S14 and S15.
- **L32** (product page design, verbatim): "tambien falta el diseño de la pagina del producto en slug". Delivered as three standalone artboards (`04-detalle-galeria`, `05-detalle-indice`, `06-detalle-vitrina`) so the same page can be compared across directions. All three use the real `apple-ipad-11-a16-chip-wi-fi` with its three real capacities and the seed's price rule, and all three mark the cart action as not available yet rather than faking a flow.
- **L33** (T11 evidence) — `Product.featured` added with an additive migration (`ALTER TABLE ... ADD COLUMN "featured" BOOLEAN NOT NULL DEFAULT false` plus an index), generated offline with `migrate diff --from-config-datasource` and applied with `migrate deploy`. `migrate status` reports both migrations applied and the schema up to date. The seed sets `featured` only on create, computed as the alphabetically first product per family; a one-off update established the initial five picks (MAC, IPAD, WATCH, AIRPODS, ACCESSORY) because the rows already existed. Proven invariant: re-running the seed afterwards left the count at 5 instead of resetting it, so manual changes survive.
- **L34** (inliner bug, fixed) — the photo-embedded variant left `../../public` glued in front of the inlined placeholder data URI on every board, so the placeholder image was broken in the canvas even though the count said it was embedded. Cause: the shorter `/placeholder.webp` alternative matched inside the longer public-prefixed reference. The pattern now prefers the public-prefixed form, and the script refuses to write a file that still references any `.webp`, so this class of silent breakage fails loudly instead of shipping.
- **L35** (direction chosen, verbatim): "me agrada galeria y detalle galeria". Direction Galería (`design/storefront/01-galeria.html`) for the landing and Detalle Galería (`04-detalle-galeria.html`) for the product page. Índice and Vitrina stay in `design/` as the alternative record and are not implemented. The artboard was marked as the chosen one through the design canvas handoff, which also records that the artboard is the visual spec and is not to be copied verbatim into the app.
