# Public catalog MVP

First versionable milestone of iTech Store: a public Apple catalog (landing, listing, detail) backed by seeded Prisma Postgres data. Cart, MercadoPago Checkout Pro, authentication and admin are explicitly out of scope for this milestone and reserved for later ones.

Branch: `main`. Each task below is a work unit and its own commit. T3 and T5 mutate remote data and data formats (`Risk: item 1`) and must stay as standalone commits.

## Specs

- **S1** — The project is "una web/ecommerce con catalogo de productos Apple, carrito de compras y mercadopago checkout pro". Cart, checkout and admin are the long-term scope, not this milestone.
- **S2** — "las dependencias del proyecto deben de ser versiones exactas": every dependency is pinned, no `^` or `~`, enforced by `saveExact: true` in `pnpm-workspace.yaml` and the committed `pnpm-lock.yaml`.
- **S3** — Milestone one is "la parte publica de landing + catalogo con seed de productos para popular la DB".
- **S4** — Catalog images come from the store owner's own existing e-commerce site ("Es mi sitio, tengo los derechos"). They live in `/public/products` and are **never committed**: the directory is gitignored and exists only for local consumption ("solo son para consumo local temporal"). The repository must contain **no reference to that source site**: no domain in code, no source URLs in data, no provenance fields, no site name in the README or in filenames. Consequence: a fresh clone seeds the database but renders no product photography, so production needs an external image host later (Cloudinary, phase 2).
- **S5** — "ya tengo la variable DATABASE_URL en .env lista para conectar con el cloud de Prisma postgres": the database is Prisma Postgres in the cloud and must be consumed through `DATABASE_URL`.
- **S6** — Product modeling follows "Producto + variantes (SKU)": a `Variant` carries its own SKU, storage, color, price and stock.
- **S7** — Seed prices and stock are "De ejemplo, reales después": sample values must be visibly marked so they are never mistaken for real prices.
- **S8** — Public UX/UI is built with the skills in `.agents`, following "Artboards primero, después código".
- **S9** — Versioning starts with "git init + .agents/ ignorado": `.agents/` is untracked and `skills-lock.json` is the contract for reinstalling it.
- **S10** — Authentication and the admin panel arrive "Después del checkout"; Better Auth and Cloudinary are phase 2.
- **S11** — Public routes are `/`, `/catalogo`, `/catalogo/[slug]`, `/contacto` and `/login`; private routes are `/admin` and `/dashboard` with Better Auth email + password.
- **S12** — `readme.md` "tiene una breve explicacón pero falta pulir" and must be written in English: "el readme.md debe de estar en ingles".
- **S13** — When a product has no images, the catalog and the product detail render the existing `/placeholder.webp`. Since images are never committed, the seed drops image references whose file is absent on the current machine, so a fresh clone shows the placeholder for every product instead of broken images.
- **S14** — `/catalogo` renders all 64 products with real URL pagination: 12 per page at `/catalogo?page=N`, plus a family filter that composes with the page parameter. Every page is a shareable, indexable URL.
- **S15** — `Product.featured` is an editorial flag in the schema, defaulting to `false`. The landing shows the featured products, capped at one per family. No admin panel exists yet, so the seed sets the flag only on create and never on update, which keeps manual changes alive across re-seeds.

- **L23** (T4 evidence) — the extraction ran twice. The first full run produced 64 products and 246 images, and verification found three defects: RAM read as disk capacity (`36GB` from a RAM-only MacBook title), generic site furniture captured as gallery media (93 distinct byte-contents across 246 files), and variant pages contributing only the first page's images. All three were fixed in the script: capacity tokens qualified by RAM/memoria/unificada are ignored in favour of SSD/almacenamiento/disco, assets used by more than 5 distinct products are dropped with the first image kept as fallback, and the per-product cap rose to 5 while later variant pages contribute new assets. The clean re-run (empty `public/products` first) produced 64 products, 170 image references, 170 files, 0 missing, 0 orphans, 68 unique SKUs, 4.2 MB, no `http` anywhere in the JSON, and no product without an image. Known limitation accepted: 39 byte-identical groups remain across different products because the same file is served under different asset keys; pruning by content hash could remove legitimate photography, so it waits for visual evidence from the catalog UI.

- **L52** (floating header, concept B, owner chose it) — the bar is now a floating pill: `top: 12px`, width `min(1200px, 100% - 32px)`, `--r-lg` radius, edged by `--e-hairline` plus `--e-float` instead of a bottom border, backdrop blur kept. Three decisions carry the work: (1) the background rose from 72% to 82% because the bar now floats over content and links over a product photo do not hold 4.5:1 at 72%; (2) an `@supports not (backdrop-filter)` fallback makes it opaque white, since translucent-but-unreadable is worse than solid; (3) no `overflow: hidden`, which would clip the mobile menu panel that hangs below the bar. The alignment trap was solved arithmetically: the bar stopped using the global `.wrap` and takes `padding-inline` equal to the page gutter MINUS the pill's 16px inset — 8px below 900, 0 below 480, 48px from 900 up — so the brand stays on the same axis as the hero text at every width instead of drifting by the inset. Confirmed in the emitted stylesheet that the whole rule survives minification.
- **L53** (mobile polish, from an owner screenshot at 320px) — two real defects, and one thing that was not a defect. The family chips wrapped into three ragged rows and ate half the screen, so below 600px they became one horizontally scrollable strip (`flex-wrap: nowrap`, `overflow-x: auto`, hidden scrollbar, children `flex: none`): same information, one line, no ragged column widths. The floating WhatsApp button sat over the iPhone chip and would permanently cover the last footer row, so a `--float-clearance` token (96px, its height plus offset plus air) is now part of the footer's bottom padding instead of an ad-hoc number. What was NOT changed: the header. In the screenshot it looked clipped, but the cut was the Next.js dev overlay tooltip sitting on top of it; the 12px gap and the pill were rendering correctly, and changing the layout to chase a dev overlay would have been a regression.
- **L54** (no horizontal padding at 320px in the header) — the alignment arithmetic from L52 left the pill with zero inner padding at 320px: page gutter 16px minus pill inset 16px is 0, so the mark sat against the rounded edge. The fix is not to add padding, which would push the brand off the page axis, but to make the inset itself a variable and halve it on narrow screens: below 480px the pill is inset 8px and the bar carries 8px of inner padding, so the sum still lands on the 16px page gutter. Content is now padded AND aligned at every width: 8+8 = 16 below 480, 16+8 = 24 below 900, 16+48 = 64 above.
- **L55** (uneven horizontal padding in the header) — the CSS padding was symmetric, but the optics were not: `.brand` starts at the content edge, while an icon button is 44px wide with a 20px glyph centred in it, so the rightmost glyph sat 12px inside the edge. Fixed with an optical outdent on `.tools` equal to that residual inset. The value is capped by the bar's own padding so the touch target never spills outside the pill: 8px below 900 (glyph lands 4px from the edge, and the 44px target ends exactly on the pill edge), the full 12px from 900 up where the bar carries 48px of padding and can absorb it. This is the same class of fix as the logo's Y offset: geometry symmetric, perception not.
- **L56** (focus ring clipped and no slide hint in the mobile filter strip) — the ring is painted outside the chip, and the scroll container clipped it above and below. Fixed with 4px of padding on every side plus an equal negative margin, which reserves room for the ring while leaving the chips exactly where they were, and 32px of right padding so the last chip can scroll clear of the new edge fade. The slide affordance is a right-edge `mask-image` on the scroller: it needs no extra element and no script, unlike an overlay pseudo-element, which would scroll away with the content. Honest limitation: the fade does not disappear at the end of the scroll, because that needs the scroll position; the right padding keeps the last chip out of the faded zone, so the cost is one permanently faded 32px strip of empty space.
- **L57** (a reformat avoided) — the first attempt added a wrapper element for the fade overlay, which left the chips one indentation level short, and running Prettier to fix it reflowed unrelated code (collapsed imports, joined a `Promise.all`, re-wrapped Spanish UI copy). That noise was rejected: the TSX was restored from HEAD and the fade moved onto the scroller itself, so the final change touches only the stylesheet and every line in it is about the strip.
- **L58** (button experiment, owner request) — the floating WhatsApp action was reduced to the mark alone at 40x40, with no white disc, no ring, no shadow and no label. The touch target survives: 4px of invisible padding takes it to 48x48, above the 44px minimum, so the visual change costs no usability. The `--float-clearance` footer reserve stayed at 96px and is now generous rather than exact; it errs on the safe side and is trivial to retune if the mark becomes the final shape. Losing the white circle has one consequence worth watching: the green mark now sits directly over content, which is fine on the white page and may lose contrast over a product photo.
- **L59** (button size, owner asked for a recommendation) — raised from 40 to 48px of glyph and stopped there. The reasoning is stated in the stylesheet so the number does not look arbitrary: a standard FAB is 56px of surface around a 24-28px glyph, and this button is glyph-only, so 48px already carries the visual weight of a ~72px FAB. Past that the green competes with the product photography it floats over, which is the difference between an available action and an obstacle. The invisible 4px padding now takes the touch target to 56x56.
- **L60** (label on hover, from an owner mock) — the button gains breathing room (8px around the 48px mark, which also makes the touch target 64px) and an ink pill label reading "Escribinos" that sits to its left and appears on hover and on keyboard focus, sliding 4px while it fades. Four decisions: the label is `aria-hidden` because the accessible name already comes from `aria-label` and duplicating it would make screen readers say it twice; it is hidden below 600px, since a label gated on hover would never appear on touch while still taking space from the icon; the hover scale moved from the anchor to the icon so the label text does not scale with it; and the global reduced-motion guard already zeroes the transition, so with motion reduced the label appears instantly instead of sliding, which is the finished state and not a hidden one.
